# ADR-0001: Use Rust as the implementation language

- Status: Accepted
- Date: 2026-08-17

## Context

The project is intended both as a useful Linux performance tool and as a systems-programming learning project.

It will interact with:

- procfs/sysfs/cgroupfs,
- kernel counters,
- process identity and races,
- binary/system interfaces later,
- potentially perf/eBPF,
- potentially privileged components.

The implementation should be efficient enough to avoid materially affecting stressed systems.

## Decision

Use Rust as the primary implementation language.

Prefer stable Rust.

## Consequences

Positive:

- strong memory safety,
- good control over allocation and data layout,
- strong parsing/error-handling ecosystem,
- good CLI ecosystem,
- credible eBPF path through Rust tooling,
- good fit for a low-overhead local diagnostic tool.

Costs:

- steeper implementation complexity than Go/Python for some tasks,
- Linux API bindings may occasionally require unsafe/FFI,
- compile times and dependency complexity require discipline.

## Alternatives considered

### Go

Strong choice for systems tooling and simple concurrency, but provides less direct learning around ownership/lifetimes/low-level boundaries targeted by this project.

### C/C++

Maximum low-level control but significantly higher memory-safety burden without a compelling project need.

### Python

Excellent for prototyping analysis, but less suitable as the primary implementation for low-overhead host telemetry and the intended learning goals.
